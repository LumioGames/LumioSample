# 0004 · Bot 数值扫描保留玩法保护并登记测量语句例外

- 日期:2026-09-28
- 状态:生效

## 背景

`BotSourceEmbedsNoGameplayTableNumbers` 按配表数字逐行扫描 Bot 源码。弱网探针的 4 Hz 发送频率、四方向取模和 xorshift 左移 13 位与矿量 4、体力消耗 13 同值，但不表达玩法规则。真实完整测试为 134/135；失败来自这些测量语句。改变频率、PRNG 或数字写法来躲避扫描会破坏测量可比性或隐藏问题。

## 决策

保留全部玩法配表数值、原数字边界匹配规则、所有非生成 Bot 文件扫描和原断言。仅为 `Client/Bots/WeakNetworkMoveScenario.cs` 中以下三条完整语句登记例外，去行尾注释和首尾空白后逐字匹配：

```csharp
_nextSend = now + Stopwatch.Frequency / 4;
_random ^= _random << 13;
(int dx, int dz) = (_random % 4) switch { 0 => (1, 0), 1 => (-1, 0), 2 => (0, 1), _ => (0, -1) };
```

每条例外必须在指定文件中恰好出现一次。缺失、重复或漂移均失败，不能自动刷新。相同语句出现在其他文件时不豁免，追加玩法代码后不豁免，禁止按整个文件、行号范围、数字值或自由注释标记豁免。新增例外需要新的决策和独立审查。

## 后果与验证

这是具名调整启发式扫描的适用范围，不是放弃“Bot 不持有玩法规则”的要求。生产 Bot、测量频率、固定种子和 PRNG 完全不变。负向回归必须拒绝额外的体力/矿量常量、测量语句后追加玩法赋值及其他文件中的同文语句；全源码扫描还检查例外数量。原真实挖矿、结算、恢复与确定性测试继续运行，零跳过。

语句格式变化会要求人工重新核对，接受这个维护成本以避免宽泛豁免。无接口、Schema、引擎版本或玩法兼容性变化。
