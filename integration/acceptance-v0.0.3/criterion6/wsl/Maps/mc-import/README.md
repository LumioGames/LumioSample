# MC 导入：映射表与损失报告（ADR-124 D10 · C11）

LumioSample 是 MC 地图导入的第一个使用方。这里放三样东西：

| 文件 | 是什么 |
| --- | --- |
| `mc-mapping.json` | 「MC 方块状态 → 我们的方块」映射表。**生成物，不手改**：规则写在 `Tools/mc-mapping.mjs`，改完 `node Tools/mc-mapping.mjs` 重写本文件，再重跑 `assess` 更新报告 |
| `*.import-report.json` | 工具 `lumio-voxel-mc-import assess` 的真实产出，一张图一份；它就是导入证据，`source` 段就是来历 |
| `SOURCES.md` | 每份报告对应的地图来历、许可、DataVersion 与窗口参数 |

导入不属于「示例」里程碑的验收范围（ADR-077 §8），导入底图也不接进 DS 默认启动。工具的用法、映射表与报告格式以 LumioVoxelEngine `crates/lumio-voxel-mc-import/README.md` 为准。

`node --test Tools/mc-mapping.test.mjs` 守五件事：映射表与生成脚本输出逐字节相同；每行的目标都是官方目录里已有的方块或 `air`，字段与方向在目标方块的范围内；没有同名同 `when` 的重复行；每份报告的映射表 / 目录 sha256 与当前文件一致、严格模式、`unmapped` 为 0、没有绝对路径；本目录里没有存档、区域文件或 `.voxel`。

## 映射表概况

50 条规则，展开后 948 个 MC 名字：`exact` 27 个、`degraded` 654 个、`dropped` 268 个（`oak_log` 按轴向拆成两行，按行计是 949）。目标全部是官方目录里已有的 24 个真名方块（C0 清单 21 种 + 原有的石头、硬墙、矿石，全部用上）或 `air`，不为映射新铸方块。

- **exact**：石头、泥土、草方块、橡木板 / 原木（竖放）/ 树叶 / 楼梯 / 台阶 / 门 / 栅栏 / 树苗、玻璃、蓝色玻璃、玻璃板、铁栏杆、冰、萤石、水、岩浆、火把（立 / 墙上）、虞美人、矮草。
- **degraded**：同类归并到最近的已有方块——各种石头与陶瓦 → `lumio.stone`；沙、砂砾、黏土等 → `lumio.dirt`；灰化土、菌丝等 → `lumio.grass_block`；其他木种与木制功能块 → 橡木对应方块；横放原木 → 竖放原木（我们的原木没有轴向）；各色玻璃 / 玻璃板 → 蓝玻璃 / 玻璃板；矿石 → `lumio.ore`；砖、金属块、羊毛、混凝土等实心装饰块 → `lumio.hard_wall`；围墙和栅栏门 → 栅栏；灯笼、灵魂火把等 → 火把；各种花与作物 → 虞美人；高草、蕨等 → 矮草；海草、海带、气泡柱 → 水源头。
- **dropped**（写成空气）：没有对应形状或只靠方块实体才有意义的东西——箱子、告示牌、床、旗帜、地毯、雪层、藤蔓、发光地衣、梯子、铁轨与红石件、按钮与压力板、活板门、头颅、传送门等。
- 楼梯的 `shape` 直接写进 `SubShapeId`；栅栏、玻璃板的连接属性不映射，由引擎现算；含水方块由工具去掉 `waterlogged` 后映射，水丢掉并计数。

## 下一步最值得补的（只作建议，不作决定）

按「补上后能少丢多少」排：

1. **石头变种**（深板岩、凝灰岩、花岗岩、安山岩、闪长岩、基岩，以及沙、砂砾）：自然地形里占降级量的九成以上。这是加方块的内容变更，不需要新的引擎能力，但要先回主会话立项。
2. **含水方块**（一格里同时有方块和水）：现在按 ADR 丢水，水下的楼梯、台阶、栅栏会留空洞；要保住需要引擎支持方块与液体共存。
3. **贴面薄片**（发光地衣、藤蔓、雪层、地毯）：现在整类丢掉；需要贴面 / 薄层形状。
4. **原木轴向**：横放的原木现在一律按竖放画；需要柱状方块带轴向字段。
5. **木种与树叶颜色**：其他木种都归成橡木；可以加方块，或做生物群系 / 方块染色。
